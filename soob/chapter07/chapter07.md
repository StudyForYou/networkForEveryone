# 7장 응용 계층, 애플리케이션에 접속한하는 단계

## Lesson30 응용 계층의 역할

- 클라이언트: 서비스를 요청하는 측
- 서버: 서비스를 제공하는 측
- 응용 계층: 사용자가 사용하는 애플리케이션(응용 프로그램)이 동작하는 곳
- 응용 계층 대표적인 프로토콜
  - HTTP / 웹 사이트 접속 / 80
  - DNS / 이름 해석 / 53
  - FTP / 파일 전송 / 20(데이터 전송), 21(명령과 응답 제어)
  - SMTP / 이메일 송신 / 25
  - POP3 / 이메일 수신 / 110

## Lesson31 HTTP 프로토콜

- 요청(request): 사용자가 URL을 입력하는 행위
- 응답(response): 서버는 사용자의 요청에 응답을 함
- 요청과 응답을 위해 HTTP 프로토콜을 사용함
- HTTP는 클라이언트와 서버가 어떻게 데이터를 교환할지 정해놓은 규칙, 80번 포트 사용
- 문자 형태로 데이터가 전송되기 때문에 필요한 부분을 파싱해주어야 함
- 구조
  - 시작 라인(start line): 요청/응답이 어떤 메시지인지를 알려줌
  - 요청에서 사용되는 시작 라인
    - HTTP 메서드, 경로, HTTP 버전으로 이루어져 있음
    - GET / Index.html HTTP/1.1
    - HTTP 메서드: 데이터를 수신하는 서버에서 어떤 작업을 해야 하는지 알려주는 용도로 사용됨
      - GET: 서버로부터 데이터를 획득함
      - POST: 서버에 데이터를 추가, 생성함
      - PUT: 서버의 데이터를 갱신함, 데이터 전체 갱신
      - PATCH: PUT과 유사, 일부 갱신
      - DELETE: 서버의 데이터를 삭제
    - 경로: 웹 페이지를 보여주기 위해 파일이나 이미지 등이 위치하는 주소
      - '/경로/파일명.확장자' 형식으로 사용
      - 경로의 구분자는 /을 사용
      - 없는 경우도 존재함 -> 서버에서 index.html이라는 파일을 자동으로 보내도록 설정한 것
    - 버전
      - HTTP 1.1 - 가장 많이 사용하는 버전 - 킵얼라이브(Keepalive) 기능: 연결이 한 번 수립되면 데이터 교환을 마칠 때까지 연결을 유지하고 데이터 교환이 끝나면 연결을 끊음
    - HTTP 2.0
      - 응용 계층에 바이너리 프레임을 추가하여 기존의 일반 텍스트 데이터를 바이너리로 변환한 후 데이터를 분할하여 보냄
      - 전송 속도가 빨라지고 오류 발생 가능성도 낮아짐
  - 응답에서 사용되는 시작 라인
    - HTTP 버전 / 응답 메시지로 이루어져 있음
    - 요청에 대한 응답 메시지
      - 1xx: 정보 / 요청을 받았으며 처리가 되고 있음을 나타냄
      - 2xx: 성공 / 요청이 성공했음을 나타냄
      - 3xx: 리다이렉션 / 클라이언트가 요청한 콘텐츠가 다른 곳에 있다는 의미
      - 4xx: 클라이언트 오류 / 클라이언트 측에 기인한 오류로 요청이 실패함
      - 5xx: 서버 오류 / 서버 측에 기인한 오류로 요청이 실패함
    - 헤더(Header)에는 클라이언트와 서버가 통신하기 위한 부가적인 정보가 포함됨
      - 호스트(Host): 서버의 도메인 이름, 포트 번호
      - 연결(Connection): 현재의 작업이 끝난 후에도 네트워크 연결 상태로 둘지 여부 제어
      - 언어(Language): 서버가 응답에 사용할 언어
    - 바디(Body)에는 데이터가 포함됨

## Lesson32 DNS 서버

- 도메인 이름: www.google.com
- DNS(Domain Name System) 서버: IP 주소를 도메인 주소로 변경해주는 것
- 원리
  - 사용자는 www.google.com을 웹 브라우저에 입력함
  - 사용자 요청은 DNS 서버로 전달됨
  - DNS 서버는 www.google.com에 해당하는 IP 주소인 142.250.206.228 전달
  - 사용자는 또 다시 IP 주소를 이용하여 웹 사이트에 접속함
  - 웹 서버는 사용자의 요청에 응답함
- DNS 서버가 www.google.com의 IP 주소를 모른다면?
  - 또 다른 DNS 서버에 질의해서 IP 주소를 전달받음
  - DNS 서버는 계층적으로 구성되어 있음
    - 단계별로 질의를 함
    - 루트부터 시작해서 .com에 대한 2단계 질의가 이루어짐
    - 마지막으로 최종 www.google.com에 대한 IP 주소를 얻게 되는 3단계 질의를 하게 됨
    - 1단계 질의: 루트, 2단계 질의: .com인지 .net인지 확인, 3단계 질의: 요청하고자 하는 IP 주소 질의

## Lesson33 DHCP 서버

- DHCP 서버
  - IP 주소를 자동으로 관리하기 위해 등장
  - 사용자들에게 IP 주소를 할당하거나 회수하는 것을 자동으로 해주는 서버
- DHCP 서버가 IP를 할당해주는 방식
  - 사용자 컴퓨터는 DHCP 서버를 찾음
  - DHCP 서버는 사용자에게 IP 주소 할당 여부를 물음
  - 사용자가 IP 주소가 필요하다고 요청을 함
  - DHCP 서버는 IP 주소를 할당해줌

## Lesson34 SMTP와 POP3 프로토콜

- SMTP: 송신자가 사용하는 프로토콜
- POP3: 수신자가 이메일을 받을 때 사용하는 프로토콜

### 1. 송신자와 메일 서버 간의 통신 - 사용자가 메일 서버에 이메일을 보내는 과정

- A는 매일 서버에 25번 포트(SMTP 프로토콜)로 통신하겠다고 알림, 그러면 메일 서버는 OK 신호와 함께 자신의 이름을 알려줌
- A라는 이름을 알리면 메일 서버는 OK로 응답함
- 이메일 주소를 메일 서버에 알려주면, 메일 서버는 OK로 응답함
- 상대방에 대한 이메일 주소를 알려주고 OK 응답을 받음
- 메일 서버에 이메일 본문을 전달하면, 메일 서버는 OK로 응답함
- 마지막으로 연결을 종료하겠다고 메일 서버에 전달하면 메일 서버는 연결을 종료함

### 2. 메일 서버 간의 통신 - 메일 서버 간에 이메일을 주고받는 과정

- 송신자 측 메일 서버는 해당 이메일을 수신자 측 메일 서버에 전달함
- 25번 포트를 사용하는 SMTP 프로토콜을 사용함 (송신자 측 메일 서버의 역할을 끝)
- 수신자 측 메일 서버는 사용자가 보낸 이메일을 B의 편지함에 저장함

### 3. 메일 서버와 수신자 간의 통신 - 수신자가 이메일을 확인하는 과정

- 과정
  - B는 110번 포트(POP3 프로토콜)로 메일 서버에 연결을 시도함
  - 연결이 수립되면 사용자가 누구인지 밝힘
  - 편지함에서 이메일을 확인하기 위한 패스워드를 알려줌 (인증된 사용자인지 확인하는 과정)
  - B는 메일 서버에 이메일이 있다는 것을 확인할 수 있음
  - 이후 해당 이메일을 B로 내려받음
  - 이메일을 내려받았으면 메일 서버와의 연결을 종료함
- POP3는 편지함에서 이메일을 가져오면 서버에서 이메일이 삭제됨
- 삭제되는 것을 원하지 않을 때에는 IMAP을 사용하면 됨

## Lesson35 응용 계층에서 사용하는 로드 밸런서

- 응용 계층에서의 로드 밸런서는 전송 계층의 로드 밸런서 기능까지 포함하고 있음
- IP 주소나 포트 외에도 URL, HTTP 헤더, 쿠키 등의 내용을 기준으로 부하를 분산시켜주는 것
- 전송 계층의 로드 밸런서가 IP나 포트 번호를 기준으로 부하를 분산시키는 것만 수행
- 응용 계층의 로드 밸런서는 서비스별로 부하를 분산시켜주는 것이 가능함
